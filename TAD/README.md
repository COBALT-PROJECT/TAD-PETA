# TAD (Tool for Attack detection)

The TAD module manages the harvesting of network telemetry and the execution of intelligent orchestrations (Machine Learning Inference + Detection) to protect Digital Twins.

## Architecture & Workflows

The current TAD implementation relies on a robust bash-based data harvesting cycle. For a step-by-step pipeline example, read [WORKFLOW.md](./WORKFLOW.md).

### 1. Data Collection (`harvester.sh`)
Fetches network data via a mounted NFS share from target infrastructure. Allows labeling the captures and runs synchronously for repeated sampling.

### 2. Feature Transformation (`pcap_to_csv.sh`)
Uses `tshark` internally to convert raw `.pcap` files into structured CSV dataset blocks containing properties like bytes, flow sizes, and IP TTLs. Allows training robust data models with offline behavior.

### 3. Model Training
Uses the extracted CSV files from Step 2 to build trained `.joblib` models using algorithms like Random Forests.

### 4. Real-time Monitoring (`realtime_monitor.py`)
The main orchestrator for the remediation loop. It polls the local `data/` directory for new CSV files generated by the NFS pipeline, performs sub-second inference using the trained models, and triggers PETA for mitigation planning.
- **Online Mode**: Targets the `/sdt-topo/` endpoint to fetch live topology and enforce patches.
- **Offline Mode**: Targets the `/cobalt-topo/` endpoint for forensic analysis against local JSON files.

**Usage**:
```bash
# Run with specific model and PETA endpoint
python3 scripts/realtime_monitor.py --model models/anomaly_detector.joblib --peta-url http://localhost:8000/sdt-topo/
```

### 5. TAD Adaptor (`tad_adaptor.py`)
A specialized translation layer decoupling TAD from the Digital Twin middleware. It handles:
- Converting Eclipse Ditto JSON into PETA topology format.
- Constructing standardized SDT update patches for mitigation enforcement.
